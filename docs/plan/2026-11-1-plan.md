# LarkBow 开发计划（2026-11-1）

## 边界约束

1. 依赖方向：`queues` 与 `logger` 不依赖任何业务模块；`storage` 依赖 `config`；`downstream` 与 `feishu` 依赖 `queues/logger/storage/config`；`downstream/api.py` 只调用本包业务函数，不直接 import storage；`feishu` 与 `downstream` 互不 import。
2. 队列是唯一跨线程通：连接上下游的媒介，飞书→派发走 Q1，下游→飞书走 Q2。除队列外，任何线程间不得共享可变业务状态。
3. 每个流水文件只由对应 logger 模块写入，其他模块调用logger模块写日志，不直接操作文件。
4. 消费循环不死：dispatcher 循环、feishu/sender 循环、sweeper 循环的每轮处理整体 try/except，任何异常静默忽略（不写文件、不打印），不得终止线程。
5. 日志失败不影响主流程：所有 `logger/*_log.write()` 内部 try/except。
6. 垃圾不进队列：/send 的全部校验（含 base64 解码、30MB、时长）在入队前完成。
7. 不重试：不做重试（含飞书发送失败、调用下游），失败则忽略进行其他。
8. 时间与地址：数据库时间用 Unix 秒；流水文件用 ISO8601（本地时区，秒级）；所有 url 字段一律存完整地址。

## 步骤 1：config 模块

### 文件：config/settings.py
功能：读取 .env 与环境变量，校验必填项，向全程序提供唯一配置入口。

**类与成员**：
- `class Settings`（dataclass）：`app_id`、`app_secret`、`port=8000`、`heartbeat_timeout=120`、`sweep_interval=30`、`dispatch_wait=3`

**注意**：日志目录 `log/`、数据目录 `data/` 的路径常量也在此定义。
**不做**：不提供运行期修改配置。

**类与成员**：

## 步骤 3：logger 模块（四个流水写手）

每个文件一个类，负责向自己的流水文件追加写 TSV 行：`__init__` 里 `mkdir log/` 并以**追加模式**打开硬编码路径 `log/<名称>.log`；各 `write` 方法拼 TSV（时间用 `now_iso()`）后写一行。每个模块另提供一个**模块级实例**（如 `registry_log = RegistryLog()`）供业务方直接调用。四个类互不依赖、不做业务判断。

### 文件：logger/dispatch_log.py —— class DispatchLog
- `write(program_id, program_name, command_id, cmd, msg_type, url, http_status, biz_status)`：正常行，字段序 = ISO8601时间/程序id/程序名/接口id/接口名/消息类型/下游url/HTTP状态码/业务状态码（9 列）；两码均为**下游返回的**
- `write_timeout(program_id, program_name, command_id, cmd, msg_type, url)`：超时行，字段序 = ISO8601时间/程序id/程序名/接口id/接口名/消息类型/下游url/超时（8 列）——两列状态码不写，行尾单写 `超时`

### 文件：logger/send_log.py —— class SendLog
- `write(program_id, program_name, user_id, msg_type, url, http_status, biz_status)`：字段序 = ISO8601时间/程序id/程序名/用户id/消息类型/下游url/HTTP状态码/业务状态码（9 列）；两码为**本层回给下游的**

### 文件：logger/feishu_log.py —— class FeishuLog
- `write_send(program_name, url, target, http_status, biz_code)`：字段序 = ISO8601时间/程序名/飞书接口url/目标用户id/HTTP状态码/业务码；两码是**飞书返回的**
- `write_receive(user_id)`：字段序 = ISO8601时间/用户id

### 文件：logger/registry_log.py —— class RegistryLog
- `write(event, program_id, program_name, base_url, command_id, cmd)`：字段序 = ISO8601时间/事件/程序id/程序名/base_url/接口id/接口名；事件 ∈ {register, dead}

## 步骤 5：storage 模块

### 文件：storage/sqlite.py
**功能**：SQLite 增删改查。

**类与成员**：
- `class Database`：
  - `__init__(self, path)`：仅存路径
  - `_connect(self)`：每操作独立连接；`row_factory=Row`；`PRAGMA foreign_keys=ON`；自动 mkdir data/
  - `init(self)`：按 database.md 建两张表（幂等 IF NOT EXISTS）
  - `register_program(self, name, base_url, cmd, path) -> tuple[int, int, bool]`：程序不存在则分配程序 id，范围100000-999999，用户保证不超999999，不做超出校验；存在则更新 base_url/heart_time；再查该程序在接口表的 `cmd`：有则更新其 path，无则分配接口 id ，范围同上，亦不校验。
  - `touch_heartbeat(self, name) -> bool`：UPDATE heart_time；rowcount=0 即未注册
  - `get_program(self, name) -> dict | None`：id/name/base_url/heart_time
  - `get_route(self, program_name, cmd) -> dict | None`： program_id/program_name/base_url/command_id/cmd/path
  - `sweep_expired(self, seconds) -> list[dict]`：查 heart_time 早于 seconds 的程序→删除其在接口表和程序表的所有记录→返回死程序清单供记 registry.log
- 模块级 `get_db() -> Database`：单例

**注意**：时间一律 `int(time.time())`；事务用 `with conn:`；不用 WAL，多线程写并发时靠 SQLite 自带锁排队等待；靠"每操作独立连接 + SQLite 内部锁"保证安全。seconds是调用方计算好的超时程序临界时间，本模块删除seconds（含）之前的程序即可，无需计算。
**不做**：不用 ORM；不做表结构迁移；不缓存连接；不在本模块写任何日志文件。

## 步骤 6：downstream 模块（注册与心跳）

**类与成员**：
- `beat(program) -> bool`：True=已刷新；False=未注册

**不做**：未注册时不做补偿动作。

## 步骤 7：downstream 模块（清扫）

### 文件：downstream/sweeper.py
**功能**：清扫线程——定时扫描超时程序，删除并记 registry.log `dead`。

**类与成员**：
- `class Sweeper`：
  - `__init__(self, interval=settings.sweep_interval, timeout=settings.heartbeat_timeout)`
  - `start(self)`：起 daemon 线程执行 `run()`
  - `run(self)`：`while True: sleep(interval); self.sweep_once()`——异常静默忽略后继续下一轮
  - `sweep_once(self)`：`db.sweep_expired(time)` → 逐个 `registry_log.write("dead", ...)`

**注意**，数据库只负责删除超过time时间的记录 ，也就是说当前模块需要用当前时间和超时秒数计算出临界时间，传给数据库操作，数据库把这个时间之前全部删除。

## 步骤 8：downstream 模块（派发）

### 文件：downstream/dispatcher.py
**功能**：Q1 消费者线程——解析"程序名 接口名 参数..."、查路由、3 秒限时 POST 下游、写 dispatch.log。

**类与成员**（模块级函数）：
- `start()`：daemon 线程执行 `_loop`
- `_loop()`：`while True: item = queues.Q1.get()` → try `_handle(item)` except → 静默忽略后继续
- `_handle(item)`：`parts = item["raw"].split()`；命中 → `_dispatch(route, item["sender"], parts[2:])`
- `_dispatch(route, sender, args)`：
  - url = route.base_url + route.path；payload = `{"sender","args"}`
  - 起**一次性子线程**跑 `_post(url, payload, result)`
  - 子线程的 requests 超时为 3 秒——到点即停，主线程检测到子线程超时结束进行其他任务；3s 内返回 → dispatch_log.write(状态码=result.status, 业务码=result.biz)；3s 未回 → 主线程 join 放弃、`dispatch_log.write_timeout(route.program_id, route.program_name, route.command_id, route.cmd, "text", url)`——行尾单写 `超时`
  - 超时/拒绝均不回用户、不重试
- `_post(url, payload, result)`：requests.post(json=payload, timeout=3) → result["status"]/result["biz"]（biz 取下游响应体 code 字段，取不到留空）；RequestException → status 缺失

**注意**：只按空格切分，绝不解释参数类型；args 全是字符串。
**不做**：不回用户任何消息；不做并发派发。

## 步骤 9：downstream 模块（发送入口）

### 文件：downstream/sender.py
**功能**：/send/text 与 /send/file 业务——全部校验在入队前完成，任务放 Q2 立即返回给下游响应状态，写 send.log。

**类与成员**：
- `class SubmitResult(NamedTuple)`：`http_status`、`code`、`message`、`data`
- `submit_text(program, target, content) -> SubmitResult`：
  1. `db.get_program` 未命中 → (400, 4001, "程序未注册: X")，send.log 照写（程序id 留空）
- `submit_file(program, target, file_name, content_base64, duration_ms) -> SubmitResult`：
  1. 同上校验
  2. 无扩展名 → (400, 4003)；base64 解码失败或为空 → (400, 4004)；>30MB → (400, 4005)；音视频且 duration_ms 缺失 → (400, 4006)
  3. 扩展名映射 file_type（doc/docx→doc、xls/xlsx→xls、ppt/pptx→ppt、pdf→pdf、mp4→mp4、其余→stream）
- 日志的HTTP 码与业务码即本层回给下游的

**注意**：content 是否为空不校验。
**不做**：不直接调飞书；不重试；不返回 message_id。

## 步骤 10：feishu 模块（发送线程）

### 文件：feishu/sender.py
**功能**：Q2 消费者线程——把发送任务真正发给飞书；每次对飞书的 HTTP 调用写一行 feishu.log；失败不重试。

**类与成员**：
- `class LarkError(Exception)`：`code`、`message`（飞书业务失败）
- `_get_client()`：lark.Client 模块级单例（app_id/secret 取 settings）
- `start()`：daemon 线程执行 `_loop`
- `_loop()`：`while True: task = Q2.get()` → try 分发 `_send_text`/`_send_file` → 任何异常静默丢弃任务记录日志，循环不退出
- `_send_text(task)`：`im.v1.message.create`（receive_id_type=open_id, msg_type=text）→ `feishu_log.write_send(program, MESSAGES_URL, target, raw.status_code, resp.code)` → `resp.success()` 为假 raise LarkError
- `_send_file(task)`：先 `im.v1.file.create`（file_type/duration）写一行 feishu.log → 拿 file_key；mp4 再取封面 image_key（`_cover_image_key()` 进程内缓存；`assets/default_cover.png` 不存在则用纯标准库生成一张纯色 PNG）→ `im.v1.message.create`（msg_type=media 带 image_key，否则 file）再写一行 feishu.log

**注意**：每次飞书 HTTP 调用后立刻写 feishu_log（发文件=两行）；HTTP 状态码与业务码都取自飞书响应。
**不做**：不重试；不修改任务内容；不做客户端限流。

## 步骤 11：feishu 模块（接收线程）

### 文件：feishu/receiver.py
**功能**：维持与飞书的 WebSocket 长连接；把单聊文本消息原样放 Q1；每收到一条写 feishu.log 接收行。

**类与成员**（模块级函数）：
- `start()`：daemon 线程内构建 `EventDispatcherHandler`（注册 `im.message.receive_v1` → `_on_message`）与 `lark.ws.Client(app_id, app_secret, event_handler=...)`，调 `client.start()`（阻塞，重连由 SDK 负责）
- `_on_message(data)`：整体 try/except（异常静默，不让回调崩掉连接）→ 去重 → `chat_type=="p2p"` 且 `message_type=="text"` → 取 sender open_id 与 content 内 text → `feishu_log.write_receive(open_id)` → `Q1.put({"sender": open_id, "raw": text})`；非单聊/非文本直接忽略

**注意**：解析命令不在这里做（原样转发，解析是 dispatcher 的事）。

## 步骤 12：HTTP 装配与程序总装

### 文件：downstream/api.py
**功能**：FastAPI 实例、Pydantic 请求模型、统一业务码信封、路由。

**类与成员**：
- `app = FastAPI(title="LarkBow")`
- 模型：`RegisterReq(program, base_url, cmd, path)`、`HeartbeatReq(program)`、`SendTextReq(program, target, content)`、`SendFileReq(program, target, file_name, content_base64, duration_ms: int | None = None)`
- 信封：`ok(code=0, message="ok", data=None)`、`fail(http_status, code, message)` → `{"code","message","data":None}`
- 异常处理器：`RequestValidationError` → `fail(400, 4007, 摘要)`（统一 422 为 400/4007）
- 路由（一行业务）：
  - `POST /register` → register.register(...)，ValueError → fail(400,4007)；成功 ok(0, "ok", data)——覆盖与新增同响应
  - `POST /heartbeat` → heartbeat.beat → True: ok() / False: fail(404, 0, f"程序未注册: {program}")
  - `POST /send/text`、`POST /send/file` → sender.submit_* → SubmitResult 转 ok/fail
  - `GET /health` → ok()

**不做**：认证、CORS、任何内联业务逻辑。

### 文件：main.py
**功能**：启动器。

**成员**：`main()`：`get_settings()`（缺凭证即退出并给指引）→ `db.init()` → `receiver.start()` → `feishu.sender.start()` → `dispatcher.start()` → `Sweeper().start()` → `uvicorn.run(api.app, host="127.0.0.1", port, access_log=False, log_level="warning")`（uvicorn 静默，控制台不刷日志）

**注意**：db.init 必须先于所有消费者线程；除主线程外全部 daemon。
**不做**：不自写信号处理（daemon+uvicorn 足够）。

## 测试

统一放 `test/` 目录（与源码目录 `src/` 并列），文件名 `test_<模块>.py`，跑法 `pytest -q`。通用纪律：**不起真实线程、不连真飞书、不碰项目根目录的 data/ 和 log/**——文件与数据库一律用 `tmp_path` 临时目录，环境与依赖一律用 `monkeypatch` 替换；测试只调模块内的函数/方法（如 `_handle`、`sweep_once`），不测 `while True` 循环本身。pytest 需加入依赖文档。

- **test_config.py**：monkeypatch 设置环境变量后断言 `get_settings()` 各字段值与类型；删掉 LARK_APP_ID 再调，断言抛 RuntimeError；把端口设成非数字，断言报错而非静默取默认。
- **test_logger.py**：四个日志类都以 `tmp_path` 为根目录实例化；各调一次 write 后读回文件，断言行数、`split("\t")` 的列数与字段顺序同 log.md；dispatch 的 `write_timeout` 断言行尾字段是 `超时` 且共 8 列；`tsv(None)` 断言输出空字段；`now_iso()` 断言秒级 ISO8601 格式。
- **test_queues.py**：Q1/Q2 各做一次 put→get 往返，断言取回对象相等；断言两个队列互不相通（Q1 空时 get 会阻塞，用 `qsize()` 判断隔离）。
- **test_storage.py**：fixture 在 tmp_path 建独立 Database 并 init；断言 `register_program` 首次返回 id≥100000、同 cmd 二次返回 overwritten=True 且接口行数不增、换 cmd 接口累积为 2；`touch_heartbeat` 对已注册/未注册分别 True/False；`get_route` 命中与未命中；把 heart_time 改小后 `sweep_expired(临界时间)` 返回死程序清单且两张表清空。
- **test_register.py / test_heartbeat.py**：register 的各参数校验分支分别断言 ValueError（非法 base_url、空 cmd、path 不以 / 开头）；走通一次注册断言返回 program_id 且 registry.log 出现 register 行（日志类指向 tmp_path）；heartbeat 对已注册/未注册分别 True/False。
- **test_sweeper.py**：临时 db 注册程序并把 heart_time 改到过去，直接调 `sweep_once()`（不起线程），断言 registry.log 出现 `dead` 行且库中记录消失。
